# HUB Gallery Scraper

Scrapy-паук для сбора данных по объектам из галереи [hub.saint-gobain.ru/gallery](https://hub.saint-gobain.ru/gallery).

Паук проходит по всем карточкам объектов в галерее, для каждого объекта собирает
использованные типы конструкций и материалов, ссылки на карточки товаров, а также
проверяет HTTP-статус каждой ссылки на материал (чтобы находить битые, 4xx, ссылки).

## Что на выходе

Два файла с одинаковым содержимым в разных форматах:

- `materials.csv`
- `materials.xlsx`

Колонки:

| Колонка              | Описание                                                        |
|----------------------|-------------------------------------------------------------------|
| `№`                  | Порядковый номер строки (с 1)                                     |
| `Ссылка на объект`   | URL карточки объекта в галерее                                    |
| `Тип конструкции`    | Иерархия типа конструкции (например, `Теплоизоляция > Наружные стены > Навесные фасадные системы`) |
| `Тип материала`      | Текстовое описание материала/решения                              |
| `Ссылка на материал` | URL карточки товара, если она есть; иначе пустая строка           |
| `Статус ответа`      | HTTP-код ответа по ссылке на материал (`200`, `404`, `ERROR` и т.д.); пустая строка, если ссылки не было |

## Технологии

- Python 3.12
- [Scrapy](https://scrapy.org/) — основной фреймворк для краулинга
- [scrapy-playwright](https://github.com/scrapy-plugins/scrapy-playwright) — рендеринг страниц через headless Chromium (нужен для обхода анти-бот защиты сайта, см. раздел «Особенности и грабли» ниже)
- [openpyxl](https://openpyxl.readthedocs.io/) — экспорт в `.xlsx`

## Установка

```bash
python -m venv venv
venv\Scripts\activate        # Windows
pip install -r req.txt
playwright install chromium
```

## Запуск

```bash
scrapy crawl HUB_gallery
```

Файлы `materials.csv` и `materials.xlsx` появятся в корне проекта по завершении краулинга.

## Как это устроено

1. **`parse`** — обходит страницы `/gallery` (с пагинацией по кнопке «Следующая страница»),
   собирает ссылки на карточки объектов (по паттерну `href^="/gallery/"`, с фильтрацией
   служебных ссылок вроде `/gallery/map` и параметров пагинации).
2. **`parse_object`** — на карточке объекта находит блоки `div.project__set-item`,
   из каждого достаёт иерархию типа конструкции (`span.term--breadcrumb-style--item`)
   и список материалов с их описанием и (если есть) ссылкой на товар.
3. **`parse_material_status`** / **`material_status_failed`** — по каждой найденной
   ссылке на материал делает отдельный запрос и фиксирует HTTP-статус ответа.

## Особенности и грабли (на будущее)

- **`ROBOTSTXT_OBEY = False`** — отключено осознанно, после ручной проверки `robots.txt`
  сайта. Включать автоматическую проверку обратно не стоит без явной необходимости —
  `RobotsTxtMiddleware` делает отдельный запрос до старта краулинга, и если он не
  промечен под Playwright, ловит те же сетевые проблемы, что и обычные запросы.
- **`scrapy-playwright` включается только через `meta={"playwright": True}`** —
  без этого флага запрос идёт через обычный (быстрый) загрузчик Scrapy. Это специально
  используется для проверки статусов ссылок на материалы — там браузер не нужен.
- **Долгая охота на сетевые сбои**: на этапе отладки паук массово падал с
  `ConnectionLost` / TLS-таймаутами при любом запросе к сайту — не помогали ни смена
  User-Agent, ни `scrapy-impersonate` (TLS-фингерпринтинг), ни настоящий headless-браузер.
  Причина оказалась банальной — включённый VPN на машине разработки. Если краулер снова
  начнёт массово падать на пустом месте — проверять VPN/прокси в первую очередь, до
  любых экспериментов с TLS и заголовками.
- **`div.field--name-label` — не универсальное имя поля**: для части категорий
  конструкции (например, «Теплоизоляция») текстовое описание материала лежит в другом
  поле, а не в `field--name-label`. Решение — брать весь текст блока материала за
  вычетом текста внутри вложенного блока со ссылкой на товар (см. XPath в `parse_object`),
  вместо того чтобы полагаться на конкретное имя класса.

## Известные незакрытые проблемы

- Часть объектов (например, `zhk-tvoi-okna`, `zhk-slavburg`) не отдаёт вообще ни одной
  строки материалов, хотя по факту материалы на странице есть. Похоже, что для этих
  объектов структура блока `div.field--name-products-set > div.field__item` отличается
  от «типовой» разметки. Требуется разбор сырого HTML конкретно такого объекта
  (`scrapy shell "<url>"`) и точечная правка селектора под найденную структуру.
